# xbm — X 书签同步到 NAS

## 0.5.0 新功能与使用

- 书签支持卡片、紧凑列表和媒体预览，浏览器会记住展示偏好；搜索、媒体类型与下载状态可组合筛选。纯文字不计为“媒体全部已下载”。
- 单条或本页批量删除会移入回收站，保留本地文件，可恢复；不影响 X 收藏，不释放磁盘空间，再次同步不会自动恢复。正在下载的书签需等待本轮下载完成后删除。
- 扩展 0.3.0 点击“自动采集历史书签”即可自动下拉，无需手动滚动；弹窗显示捕获条数、滚动轮数、耗时及待传数，可随时停止。关闭弹窗仍继续运行。
- 保持已登录的 X 书签页打开。每轮最多滚动 300 次，连续约 22 秒无新增时停止并提示可能不完整，只有 X 明确返回结束信号才标记列表结束。总数未知，不显示完成百分比。
- “快速同步”只采集最近内容，定时同步也使用快速模式。先更新 NAS，再重新加载扩展并刷新 X 页面。

把 X（Twitter）书签里的推文自动同步到 NAS 本地：图片、视频、长文章全文。

- 路线：**Chrome 扩展被动拦截 + 服务端下载**（不使用付费 API；仍受登录、限流和页面改版影响）
- 详细设计见 [DESIGN.md](DESIGN.md)

## 安装与首次使用

### 飞牛 NAS：安装独立 FPK（推荐）

适用：x86_64 飞牛 fnOS 1.2.0401 及以上。独立包已经包含 Python、服务端和下载依赖，无需安装 Docker、Python 或手动创建服务。

1. 打开 [最新 Release](https://github.com/dengyintao/x-bookmark-sync/releases/latest)，下载 `.fpk` 和 `x-bookmark-extension-*.zip`。可同时下载 `SHA256SUMS` 校验文件完整性。
2. 登录飞牛网页管理后台，打开 **应用中心 → 手动安装**，选择 FPK，按向导选择有足够空间的存储位置并安装。建议至少预留 1 GB 程序安装空间；书签媒体需要另计。
3. 在应用中心启动“X 书签库”，点击桌面图标；也可访问 `http://NAS局域网IP:8765/`。
4. 新安装会创建空书签库。按下面的步骤安装浏览器扩展并设置 NAS 地址，完成第一次同步。

若 NAS 上已有手工部署的 `xbm.service`，先备份数据并停止旧服务以释放 8765 端口；详见下方“升级、备份与旧服务迁移”。不要同时启动两个服务。

### 安装浏览器扩展

1. 解压 Release 的 `x-bookmark-extension-*.zip` 到一个固定目录，之后不要移动或删除这个目录。
2. Chrome / Edge 打开 `chrome://extensions` / `edge://extensions`，启用 **开发者模式**，点击 **加载已解压的扩展程序**，选择包含 `manifest.json` 的目录。
3. 点扩展图标，进入设置，将服务端地址设为 `http://NAS局域网IP:8765`，例如 `http://192.168.1.10:8765`，点击 **测试连接**。这里不能填浏览器本机的 `127.0.0.1`，也不要填 `/#runs` 等页面路径。
4. 在同一浏览器登录 `x.com`，打开自己的 **书签** 页面。确认插件识别的 @用户名正确，再点 **自动采集历史书签**；日常只更新最近内容可用 **快速同步**。插件使用已有标签页，不会新开标签页。
5. 保留已登录的书签页，以便定时采集。安装或更新扩展后要刷新 X 页面；首次同步只采集当前流程能加载到的书签，历史回填受页面加载、限流和轮数限制。

扩展详细设置见 [extension/README.md](extension/README.md)。

### 判断同步是否成功

1. 查看扩展任务状态：**捕获数量**是浏览器采集数量；**待传数量**大于零表示仍未送达 NAS。出现“等待补传 / Failed to fetch”时检查连接，队列会保留并重试。
2. 打开 NAS 管理页，在左侧选择登录的 X 账户，进入 **同步记录**，确认有新的接收记录和收到/新增数量。插件捕获 0 条并不代表已有书签已全部同步。
3. 进入 **全部书签**查找刚同步的书签；进入 **下载队列**检查媒体状态。元数据提交成功与媒体下载完成是两个阶段。
4. 切换 X 账号后，插件按新识别的 @用户名分库；NAS 页面也需要切换对应账户。旧无账户数据可通过 **旧数据归属**预览后迁入，具体流程见下文。

### 配置数据目录、代理和日志

FPK 的配置位于 `/var/apps/x-bookmark-sync/etc/config.toml`，默认数据目录为 `/var/apps/x-bookmark-sync/var/data`，日志为 `/var/apps/x-bookmark-sync/var/server.log`。这些路径链接到所选存储空间，升级不会覆盖配置和数据。

需要自定义目录或应用代理时，先在应用中心停止程序，编辑配置，再启动：

```toml
[data]
root = "/your/accessible/path/x-bookmarks"

[proxy]
url = "http://127.0.0.1:7890" # 可选；已有透明代理时通常留空或省略

[migration]
backup_dir = "/your/accessible/path/ownership-backups"
```

自定义路径必须允许专用用户 `x-bookmark-sync` 遍历父目录并读写数据目录。飞牛个人目录可能受 `trimacl` 控制，普通 `setfacl` 授权仍可能无法写入；遇到只读数据库错误，优先停服复制到应用默认数据目录，并将数据库中已有媒体的绝对路径一并调整，不要直接修改全卷权限。不要将代理凭据或 X cookie 提交到 Git。浏览器扩展采集无需向 NAS 提供 X cookie。

### 升级、备份与旧服务迁移

- **FPK 升级**：备份配置、整个数据目录和迁移备份目录后，通过飞牛应用中心安装新版 FPK；安装工具可能跳过已安装应用，必须核对实际运行版本。启动后检查版本、账户、书签数量和同步记录。扩展有新版本时更新其目录，在扩展管理页点“重新加载”，再刷新 X 页面。
- **一致性备份**：停止应用后再复制整个数据目录，包含 `.xbm`、`accounts` 和媒体。若配置单独指定了下载或迁移备份目录，也应一并备份。不要只复制单个数据库后漏掉账户库。
- **旧 systemd 部署迁移**：备份后执行 `sudo systemctl disable --now xbm.service`；安装新 FPK，停止应用，将旧 `config.toml` 复制到 FPK 配置目录。保持旧数据路径并授予应用用户访问权限，或停服复制到新目录后修改 `[data].root`。确认权限、启动和数据无误后再决定是否清理旧程序。
- **卸载**：选择飞牛的“保留应用数据”，并事先备份。卸载脚本不会主动删除书签，但系统选择删除应用数据仍可能清除默认目录。

### 常见问题

| 现象 | 检查方法 |
| --- | --- |
| FPK 启动失败 | 查看 `server.log`，确认 8765 端口未被旧服务占用、安装卷有剩余空间、数据路径可写。 |
| 插件连接失败 / 等待补传 | 从插件所在电脑打开 `http://NAS地址:8765/api/status`；检查 IP、端口、防火墙和 ZeroTier 路由。 |
| 未识别 X 账户 | 刷新已登录的 X 页面，确认本人资料入口可用；不要将作者账号当作登录账号。 |
| 同步记录收到 0 条 | 确认 X 书签页已加载且有书签，刷新页面后重试；查看插件捕获数量和错误。 |
| 书签已收到但媒体失败 | 检查 NAS 到媒体 CDN 的网络、代理、磁盘空间及下载队列错误；网络恢复后重试失败任务。 |

API 当前没有独立鉴权，请仅在可信局域网或受控 VPN 中使用，勿直接开放到公网。

### 其他 NAS / 本机：Python 部署

需要 Python 3.11+。先克隆仓库并进入目录：

```bash
git clone https://github.com/dengyintao/x-bookmark-sync.git
cd x-bookmark-sync
python3 -m venv .venv
. .venv/bin/activate
pip install -e .
cp config.example.toml config.toml
# 编辑 config.toml 中的 data.root 和可选代理配置
xbm --config config.toml serve --port 8765
```

打开 `http://主机IP:8765/`，再按上述步骤设置浏览器扩展。需要 HLS 下载时额外安装 FFmpeg；长期运行可自行配置 systemd。

## 目录结构

```text
extension/
  manifest.json / injected.js  # MAIN world：hook fetch/XHR，捕获书签 GraphQL
  content.js                   # 自动滚动采集 + 数据转发
  background.js                # 定时采集、推送服务端、失败本地队列
  popup.html/js / options.html/js
src/xbm/
  server.py       # Web 服务 + POST /api/ingest（去重入库、CORS）
  cli.py          # 命令行入口（serve / 备用抓取器调试）
  config.py       # config.toml 加载
  db.py           # sqlite：去重集合 / watermark / 运行日志
  auth.py         # （备用）twifork 登录与 cookie 管理
  fetcher.py      # （备用）twifork 书签增量抓取
  downloader.py   # （M2）CDN 直链下载图片/视频
  articles.py     # （M3）长文章全文 → Markdown
  notify.py       # 失败告警（Bark/Telegram/日志）
```

## 运维要点

- 当前部署形态：独立 Python HTTP 服务，可由 systemd 常驻运行；内置 Web 管理界面，0.4.1 起提供独立飞牛安装包。
- 扩展与服务端走同一份 ingest 协议（`POST /api/ingest`），采集器可替换；备选采集器见 DESIGN.md §2.2（Headless 浏览器）。
- 媒体下载走 CDN 签名直链，免登录、无 cookie 维护。

## NAS 管理界面（0.3.0）

启动服务后打开 `http://NAS地址:8765/`：

- **全部书签**：搜索正文、作者、用户名，按媒体类型筛选，分页浏览，查看正文、原文链接与本地已下载的图片/视频。
- **同步记录**：显示 NAS 收到的批次，含接收时间、采集时间、来源、收到/新增/重复数量和媒体入队数。一次插件同步可能拆成多个批次；插件尚未送达的数据不会出现在这里。旧记录缺失的计数显示 `—`。
- **下载队列**：已传输字节、总大小、速度、百分比、重试次数、退避时间与错误原因，每 3 秒更新；可立即重试失败任务。HLS/总大小未知的任务只显示状态，不伪造百分比。

界面无需外部 CDN 或构建工具，随 Python 包分发。数据库升级自动补列并保留原数据；升级生产服务前请备份 `.xbm/xbm.db`。

### 飞牛独立安装包（0.4.1 起）

从 GitHub Release 下载 `x-bookmark-sync-0.4.1.fpk`，在飞牛应用中心手动安装并启动，点击桌面“X 书签库”打开 8765 端口。支持 x86_64 fnOS 1.2.0401+；包内包含 Python 运行时、Web 服务、gallery-dl 和 FFmpeg，无需预装 Python、Docker、systemd 服务，也不需要在安装时联网下载依赖。

应用使用专用用户运行。配置在 `TRIM_PKGETC/config.toml`，书签和媒体在 `TRIM_PKGVAR/data`，迁移备份在 `TRIM_PKGVAR/migrations`，日志在 `TRIM_PKGVAR/server.log`。升级保留配置和数据；卸载脚本不主动删除它们，卸载时仍应选择系统的“保留应用数据”并提前备份。

旧桌面入口包/手工部署用户：先备份原配置和书签，停止原 `xbm.service` 释放 8765 端口，再安装/升级 FPK。新包不会自动复制或接管旧目录；将旧数据复制到新数据目录并赋予应用用户权限后再启动，或在配置中指定应用用户可访问的旧目录。旧服务仍存在时不要同时启动。扩展 NAS 地址不变。

服务直接提供 HTTP，不通过飞牛登录网关；请在可信私有网络使用。

## 按登录的 X 账户分库（0.3.1 / 扩展 0.2.4）

扩展从 X 导航中的**本人资料入口**读取当前登录的 @用户名，不从书签作者推断。捕获请求开始时绑定账户，账户切换后丢弃旧请求响应；待传数据携带原账户，不随之后的登录变化重新归属。无法识别账户时停止新采集，提示刷新页面。升级扩展后必须刷新 X 页面。

NAS 左侧账户选择器同时切换书签、同步记录、下载队列和统计。每个账户有独立 SQLite 数据库与媒体目录：

- 数据库：`{data.root}/accounts/{用户名}/.xbm/xbm.db`
- 媒体：`{原 media_dir}/accounts/{用户名}/{tweet_id}/`
- 旧版数据和无账户标记的旧待传队列继续留在“未归属（旧版本数据）”，原路径不变；不会猜测或自动合并。

同一推文被不同账户收藏时分别入库和下载。@用户名忽略大小写；修改 X 用户名会建立新的库，目前不自动合并更名前后的账户。备用 CLI 采集器仍写入未归属库。

账户选择属于存储分类，**不是访问权限或独立鉴权**；本服务继续仅用于可信私有网络。旧客户端仍可向未归属库投递；新扩展向带账户的接口发送数据并验证回执账户，旧服务端会拒绝该接口，防止静默混存。

## 旧数据归属管理（0.4.0 / 扩展 0.2.5）

管理页顶部点击 **旧数据归属**：

1. 在浏览器打开或刷新已登录的 X 页面。插件只读取本人资料入口的 @用户名，不读取 cookie、不触发书签采集；账户变化时自动报告 NAS，离线时保存识别信息并重试。
2. 点击“读取插件识别的账户”，或选择已知账户。最近识别信息会展示时间；多浏览器/多标签页时需确认目标账户，不自动猜测归属。
3. 点击“预览归属”检查书签、媒体、同步记录与重复数量。未归属库为空时不再迁移；文件缺失/大小不符、活动下载或预览后数据变化时阻止执行。
4. 点击“确认归属到 @用户名”。后台任务先备份，再合并和校验；关闭页面不会取消任务。任务记录持久保存状态、数量、错误及备份位置。
5. 完成记录支持“撤销此次归属”。只在两个库都未发生后续变化时恢复；有新数据或下载状态变化就拒绝覆盖。旧版本导入的迁移回执仅供查阅，不能用新版安全撤销。

命令行使用运行中的服务，复用同一套锁、备份和任务记录：

```sh
xbm migrate-legacy --account @your_handle            # 只预览
xbm migrate-legacy --account @your_handle --apply    # 创建后台任务
xbm migrate-legacy --rollback TASK_ID               # 安全撤销
# 连接其他服务可加 --server http://NAS地址:8765
```

默认备份位于运行用户的 `~/.local/share/xbm/migrations/{任务ID}/`，可在配置中指定另一块有空间的卷：

```toml
[migration]
backup_dir = "/path/to/ownership-backups"
```

备份包含 `source.db`、`target.db`、被改写的原元数据及迁移回执；原媒体文件始终保留。同卷采用硬链接，不额外复制大文件；跨卷先检查空间再复制。自动失败回滚和安全撤销仅清理本任务创建的目标链接，不删除原媒体或备份。

归属任务日志位于 `{data.root}/.xbm/operations.db`。两个库使用 SQLite DELETE 日志模式下的附加数据库事务，原库清空与目标库写入一起提交。服务重启会用目标库事务标记确认是否已经提交，避免重复迁移；未提交任务回滚并清理临时文件，记录为中断。此前离线工具在运行用户家目录产生的 `xbm-account-migration-*/receipt.json` 会被导入历史记录，不会重新执行。

备份与原媒体应保留到确认无误。备份是停服灾难恢复的依据；不要直接覆盖仍有新数据的数据库。账户分类仍不等于访问鉴权，本服务继续用于可信私有网络。

## 自动构建与 Release

GitHub Actions 在 main 推送、PR 或手动触发时执行服务端和扩展行为测试，随后构建并上传 `xbm-release-assets` Artifact（保留 30 天）。推送 `v{项目版本}` 标签会在相同检查通过后自动创建正式 GitHub Release，附带 FPK、Python wheel、插件 ZIP、源码 tar.gz 和 SHA256SUMS。

版本标签、pyproject.toml 和 FPK manifest 必须一致；扩展 ZIP 使用独立的 manifest 版本。fnpack 固定为官方 1.2.3，下载后验证 SHA256。FPK 在 Ubuntu 22.04 x86_64 构建并冻结 Python 运行环境，构建阶段验证独立启停、升级保留数据和 HTTP 界面。

本地复现：

```sh
python3 -m pip install "setuptools>=61" wheel
python3 -m pip install . pyinstaller==6.16.0 imageio-ffmpeg==0.6.0 wheel
# Linux x86_64（推荐使用 Actions）
python3 scripts/build_release.py --fnpack /path/to/fnpack --tag v0.4.1
# 所有产物位于 dist/release/
```

源码包来自当前提交的 git archive；本地未提交改动不会打入源码包。发布前先提交改动，再推送对应版本标签。

### 发布前诊断与升级核验（开发中）

NAS 页面的“连接诊断”检查数据库和媒体目录是否可写、剩余空间及服务版本，可以导出脱敏 JSON。报告不包含书签正文、用户名、目录路径或代理密钥；它不代表 X 登录或历史采集完整性检查已经通过。

**不能把 `appcenter-cli install-fpk` 返回成功当成完成升级。** 已观察到对已安装应用跳过更新的情况。优先通过飞牛应用中心的安装界面操作，随后显式核对目标版本：

```bash
python3 scripts/check_deployment.py --url http://NAS-IP:8765 --expect 0.5.0
```

若版本不符，检查失败并返回非零退出码。不要通过卸载删除数据来尝试修复。应用中心升级及回滚仍需按 [发布验收清单](docs/RELEASE_CHECKLIST.md) 在隔离环境验证。

新的独立运行包提供元数据备份命令（旧版 0.5.0 包尚不含此命令）：

```bash
/var/apps/x-bookmark-sync/target/server/xbm --backup-metadata \
  /var/apps/x-bookmark-sync/etc/config.toml /YOUR-BACKUP-VOLUME/xbm-backup-UNIQUE
```

目标目录必须不存在且应用用户有写权限。备份包含配置与各账户 SQLite 快照，校验后才公布为完整目录；包含敏感配置，目录权限为 700。**媒体不包含在此备份中**，仍需独立备份。用于版本升级前的快照应先停止应用，避免多个账户在不同时间点产生变化。恢复流程仍在发布验收清单内，不能把创建快照成功等同于恢复验收通过。


### 开箱即用连接（0.6.1 / 扩展 0.4.1）

1. 安装 NAS 服务，管理密码可留空。可信局域网内通过 NAS 的 IP 地址打开书签库即可使用，无需另外找密钥。
2. 在扩展设置填写 NAS 地址，点击“连接 NAS”。
3. 在自动打开的 NAS 页面点击“允许同步”，返回扩展后自动显示连接成功，无需复制配对码。等待确认时保持扩展设置页打开；请求 5 分钟有效，超时可重新连接。
4. 打开 X 书签页，在扩展弹窗启动自动采集，无需手动下拉。已有待传内容在连接后自动补传。

已有有效连接在升级后继续使用，不清空历史和待传队列。被撤销或过期的连接需要再次确认。旧版 NAS 可通过扩展的“高级：备用配对码”继续连接，旧配对码接口保持兼容。

“浏览器连接”中可查看、撤销连接；扩展凭据只允许提交书签、上报账户和查看同步统计，不能读取书签正文、媒体或管理数据。凭据与 NAS 的协议、主机、端口绑定，只保存在当前浏览器，不通过 Chrome 账户同步。当前设计面向个人所有者的多个 X 账户，不提供多人之间的租户隔离。

**访问范围与高级安全设置：**免登录仅适用于客户端和访问地址均为回环、RFC1918 私有 IPv4 或 IPv6 ULA 的 IP 地址。域名、外网地址访问仍要求管理密码或恢复密钥；不会信任客户端自报的转发头。免登录意味着可信局域网中的其他设备也能打开管理页，请仅在自己的可信网络使用；不要将服务端口直接映射到公网。反向代理应保留真实 Host 和 Origin，不能依赖将公网请求伪装成本机请求的代理来隔离访问。

在“浏览器连接 → 高级安全设置”可开启“局域网也要求登录”，首次设置至少 12 个字符的密码。启用时旧管理会话立即失效，扩展连接不受影响。已有密码在升级后默认继续要求登录；如需免登录，先正常登录，再关闭此选项。HTTP 不提供传输加密，远程访问请使用 HTTPS 或可信 VPN。

管理密码忘记时，可在 NAS 本机运行 `xbm --config config.toml access-key` 读取恢复密钥。`--reset` 会撤销管理会话、扩展连接和待确认请求，删除管理密码及安全策略并生成新恢复密钥，恢复默认局域网免登录。不要分享命令输出。独立包使用应用目录的 `target/server/xbm` 和实际配置路径。数据库快照不包含访问凭据，恢复后需重新连接浏览器。

### 回收站与存储预算（0.6.0 开发版本）

“删除”可恢复且保留文件；在回收站选择书签后，“彻底删除所选”会删除正文与该账户的本地媒体，无法恢复，不影响 X 上的收藏。仍被其他记录引用的路径会保留；其他账户的硬链接不受影响。程序保留最小书签 ID 去重标记，避免再次同步重新下载已彻底删除的内容。文件清理失败会保留待清理记录，服务运行时后台重试，可在“存储管理”查看。

“存储管理”还可按账户选择全部媒体、仅图片、仅视频/动图、仅书签，以及暂停新任务、设置媒体预算（GiB）。预算按下载记录计算，达到后暂停领取新任务；正在执行的任务允许完成，因此可能超过预算。切换范围不删除文件，也不会丢弃未领取的任务。卷剩余空间与媒体记录字节数不同，硬链接、临时文件和文件系统回收策略都会影响实际占用。

### 在独立目录恢复备份

```bash
xbm --config /path/to/config.toml backup --out /backup/xbm-snapshot-UNIQUE
xbm restore --source /backup/xbm-snapshot-UNIQUE --out /restore/xbm-NEW   --media-source /backup/separate-media-root
```

恢复目标必须不存在。配置、数据库和媒体路径会指向新目录，原服务不被覆盖；恢复配置保留通知及代理等敏感设置，仍需妥善保护。`--media-source` 是另外备份的媒体根目录，可省略。缺失媒体会标记为待下载，不会假装已恢复；未恢复管理密码及浏览器凭据，首次启动后需重新建立访问。请在隔离环境验证数量、文件、账户及同步行为后再安排正式切换。

管理页面的修改操作先获取一次性操作凭据；凭据接口不允许跨域读取，凭据只使用一次并在 60 秒后失效。这能兼容来源请求头被浏览器或网络改写的情况。旧版页面需要刷新，扩展提交不依赖此网页操作凭据。

数据存储、传输、删除及备份的具体行为见 [数据与隐私说明](PRIVACY.md)。

扩展从 0.3.x 更新时，会保留对原来已配置的 0.5.x NAS 地址的兼容上传。该兼容仅适用于旧服务，不包含配对保护；服务升级到要求配对的版本后，扩展会停止匿名上传并保留队列，直到完成配对。新安装不会自动开启旧版兼容。
